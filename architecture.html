Contact Brief · execution boundaries

One person at a time. The package compiles evidence supplied by the host; it does not browse, discover people or send messages.

Optional host research

Native LinkedIn and X

The host resolves identity and inspects profiles and authored activity. A name match alone is insufficient.

Optional email lookup

Codex Exa plugin or an authorized Fiber/direct API route may return at most one provider-reported address. Exa is not used for identity or social research.

Optional mailbox check

AfterShip runs only with exact-address authorization. Its result is separate from email attribution and identity.

These are host capabilities, not part of the offline compiler. Provider calls, browser work and mailbox checks are not implied by a successful build.

1 · Set up

Resolve the tool path

Find scripts/contact_brief.py beside the skill, or two levels above it in the portable package. Put the virtual environment and run files in a writable directory outside the package.

2 · Compile and validate

Offline Python compiler

3 · Review

Brief and optional draft

Writes cited Markdown and contact-brief.v1 JSON to the chosen run directory. Any draft is unsent.

Optional JobSSS handoff

With approval, import the JSON brief into a profile. JobSSS reads it natively, can reconcile safe repeats, and keeps imported contacts unapproved.

Authority boundary

Read back exact persisted records. JobSSS owns its state; Contact Brief grants no approval and neither package sends outreach.
